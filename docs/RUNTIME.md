# Runtime contracts

The CLI accepts a job URL, a JD file, pasted text, clipboard text where supported,
and batch inputs. The public offline example uses a local fictional JD. Network
and live ATS retrieval require separate online verification and are not exercised
by the offline test suite.

The deterministic pipeline ingests source and requisition identity, detects the
ATS, extracts P0-P3 requirements, verifies immutable source anchors, routes the
role, attaches semantic annotations, resolves evidence entities, maps requirements,
validates constraints, selects employment before residual projects, curates skills,
and plans the resume/cover pair. Configurable role inventories are checked against
their declared count. Related artifacts cannot create separate project identities.

Candidate authority is explicit configuration. Capability possession cannot assign
historical usage to an employer. Chronology establishes duration; project counts
and tool mentions do not. Employment, project ownership, numerical scale, modeled
results, and realized outcomes retain their provenance. Entity-specific historical,
model-attribution, project/employment and completed-deliverable rules are configured
in candidate_facts.json, not hardcoded to a specific person.

Independent gates retain truth, ATS >=85, human >=85, parser, one-page geometry,
cover, interview defensibility, roundtrip and final audit boundaries. ATS weights
are internal simulations, not proprietary vendor scores or hiring guarantees.
ATS detection can be exact while the employer's enabled scoring configuration
remains unknown. No sample gate receipt is a production acceptance.

Model adapters, semantic escalation, inference budgeting and durable writer receipts
remain available. The authenticated `codex exec` transport, CODEX_HOME catalog and
credential-variable names are functional inference integration, not development
metadata. The existing model target is gpt-6.1-sol with high/xhigh reasoning;
preflight requires the authenticated catalog to support the target. Qwen probes use
an explicit local Ollama endpoint. Enabling an adapter can consume usage; the public
tests mock transports, disable advisory flags and never run live inference.

A complete passing gate chain releases the exact run artifacts. An explicit user
override produces labeled unreleased output; it cannot turn a failed gate into a
normal release. Artifact delivery re-resolves canonical authority and verifies hashes.
Daily Output accumulates independent copies of two PDFs and two DOCX files per
eligible completed job; receipts remain outside that folder. Test outputs are ignored.

No production state, rollback archive, private corpus, migration package, application
history, active GitHub workflow, credentials, or model weights are distributed.
This source snapshot supports independently configured local operation. Public
publication does not deploy or connect it to any private installation.

`examples/run` contains illustrative outputs from the fictional offline pipeline. The manifest intentionally stops before writing or release; it is not an approved application or a resumable production run.
